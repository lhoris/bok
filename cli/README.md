# `bok` CLI — Walking Skeleton (ROADMAP M1)

Vendor-neutral, dependency-light (Python stdlib + PyYAML). Implements the two
commands that let `examples/acme-billing` be regenerated by tooling instead of
by hand — proving the design's models connect into one runnable flow.

## Commands

```bash
python cli/bok.py init     <project> --project NAME --context CTX  # scaffold bok/ + bok.yaml
python cli/bok.py discover <project> --scope S --source src        # mine candidate KUs from code
python cli/bok.py status   <project>                     # KU count, confidence dist, dangling
python cli/bok.py compile  <project>                     # authored KUs -> catalog.yaml + graph.json
python cli/bok.py ready    <project> --scope S --purpose P # coverage -> lights -> hard gate -> tier
```

- **discover** (M2, design/02 §1 + research/02 software-archaeology): deterministic
  archaeology (no LLM) — Python `ast` import graph -> package KUs + depends-on
  relations; SQL `CREATE TABLE` -> data-model KUs; git change-heatmap (LOC
  fallback) -> priority. Emits `confidence: inferred`, `status: draft` KUs with
  code provenance; idempotent (never clobbers existing ids). See
  `examples/mini-shop/`.

- **compile** (design/05 D20/D21): parses every `bok/<context>/**/*.md`, validates
  the KU schema (required fields, valid `kind`/`confidence`, `provenance` ≥ 1),
  writes `bok/_system/catalog.yaml` (L1 index) + `graph.json`, and detects
  **dangling relations** (a `relations.target` id that no KU authors). Schema
  errors are fatal (exit 1) — the pre-commit gate.
- **ready** (design/04 B.3/B.4): reads `coverage.yaml` + compiled confidences,
  computes each area's traffic light, applies the **hard gate** (any `critical`
  area red ⇒ NOT READY regardless of score), the weighted **score**, and the
  **Readiness Tier** (R0–R4). `--purpose` maps to a target tier via `bok.yaml`.
  Exit 0 = READY, 2 = NOT READY.

Run against the example:
```bash
python cli/bok.py compile examples/acme-billing
python cli/bok.py ready   examples/acme-billing --scope billing --purpose feature
```

## Scope
In: init, discover (deterministic archaeology), status, compile, schema check,
dangling detection, ready (lights/hard-gate/score/tier), pre-commit hook.
Out (later milestones): context (canonicalize/type), validate, staleness, assemble.

## M2 Findings (검증 결과)
`bok discover`를 `examples/mini-shop`에 돌려 6개 후보 KU를 자동 생성했다.
- **초기 confidence는 전부 `inferred`** (단일 자동 근거). ROADMAP M2의 검증 질문에 대한 답:
  자동 발굴은 초안을 주지만 신뢰를 주지 않는다 — `ready`는 여전히 NOT READY(R0, score 0).
- 도구가 **코드로 알 수 있는 것(구조·의존·테이블)과 없는 것(업무 규칙·의도)을 스스로 구분**하고
  후자를 `## 열린 질문`에 명시 → human-externalization(M4)의 대상을 자동 표식.
- **발굴 ≠ 이해 ≠ 준비**가 실행으로 증명됨. 이것이 생성-only 도구(DeepWiki류)와의 분기점.

## M1 Findings (검증 결과 — 설계로 환류)

M1의 목적은 코드가 아니라 **설계의 검증**이다. 예제를 도구로 돌려 세 가지가 드러났다.

1. **완결성(completeness)은 confidence만으로 측정되지 않는다.**
   초기 구현은 영역 status를 "존재하는 KU의 confidence"로만 계산 → `context-and-scope`가
   green으로 나왔으나, 사람은 "아직 문서화 안 된 컨테이너가 있다"는 이유로 amber로 판단했다.
   → design/04 B.3의 "미해소 gap 존재 → amber"를 **`open_gap` 저작 플래그**로 구현해 해소.
   이는 자동화의 경계를 보여준다: **known-unknown은 사람이 선언**하고 도구가 반영한다.

2. **테스트가 verdict 버그를 잡았다.** 초기 verdict는 `tier.startswith(target)`라
   R4가 R3 목표를 만족하지 못했다(all-green 프로젝트가 NOT READY로 오판).
   → tier **순위 비교**(R4 ≥ R3)로 수정. "이전 산출물을 그대로 신뢰하지 않는다"(헌장)를
   도구 자신에게도 적용.

3. **도구가 사람의 낙관을 교정했다.** 손으로 쓴 readiness-report는 Tier를 R1로 적었으나,
   R1(Mapped)은 data-model green을 요구하는데 red이므로 도구는 **R0**로 판정.
   → 객관적 게이트가 주관적 추정을 바로잡는 BOK의 가치를 그대로 실증.

이 발견들은 ROADMAP M1의 "검증 질문"에 대한 답이며, 완결성 모델링은 향후 정식화 대상이다.
